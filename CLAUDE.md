## Концепт
Паперовий ніндзя з мечем біжить по світу, що є одним великим аркушем паперу, який хтось
повільно згортає. Мета повної гри: дістатися центру аркуша. Персонаж вразливий до вогню
й води та вміє трансформуватися в орігамі-форми. Прототип охоплює одну локацію: гірський рівень.

## Стек і версії
- TypeScript + Vite у режимі multi-page (кілька HTML-входів).
- Phaser з Arcade Physics (Matter.js для прототипу не потрібен).
  За замовчуванням — остання стабільна 3.x. Якщо на момент старту вже вийшов стабільний
  Phaser 4, коротко порівняй варіанти в плані й запитай мене.
- Node — актуальна Active LTS (очікувано 24; перевір). Caddy — актуальна 2.x alpine.
  Усі образи Docker, npm-залежності й GitHub Actions мають точні версії.
- Контентні сторінки — статичний HTML без JS-фреймворку. Phaser вантажиться тільки на /play/.
- Жодних зовнішніх ассетів для гри: уся графіка малюється кодом (Graphics, генеровані текстури).
- Без бекенду, збірка у статичний бандл.

## Обсяг гри
1. Рух: біг, стрибок, змінна висота стрибка, coyote time, input buffer.
   Клавіатура: стрілки/WASD — рух, Space — стрибок, J — атака, R — рестарт.
   Дотик: віртуальні кнопки ←, →, Jump, Attack, з multi-touch (біг + стрибок + атака
   одночасно). Для портретної орієнтації — підказка "Rotate your device".
2. Меч: атака по натисканню, хітбокс. Атака — шар поверх станів (дозволена на землі й у стрибку).
   Ворог: ходить між двома точками, при контакті знімає 20 HP, гине від 2 ударів.
3. Вогонь: вогняні зони з частинками. Папір у зоні поступово обгорає (темніючий край
   повзе по спрайту, через маску). Здоров'я 100 HP, вогонь знімає ~35 HP/с, тобто
   є ~3 секунди, щоб вискочити. Обгорілість зберігається до респавну.
   Після шкоди — 1 с невразливості з миганням.
4. Планер: утримання Space під час падіння складає персонажа в паперовий літачок
   (на мобільному — утримання Jump у повітрі). Спрощена модель: повільне падіння,
   горизонтальна швидкість. ↑/↓ змінюють нахил: вниз — швидше й нижче,
   вгору — повільніше, але довше. Висхідна вітрова зона підкидає планер угору (без шкоди).
5. Рівень на ~2–3 екрани: платформи, вогонь, ворог, прірва, яку без планера не пройти,
   чекпоінт і фініш.
6. Смерть (0 HP або падіння в прірву) → оверлей "You burned / You fell" → R або тап →
   респавн на останньому чекпоінті. Фініш → оверлей "Level complete" + рестарт.
7. Базова роздільна здатність 960×540, Scale.FIT, камера стежить за гравцем у межах рівня.
   Гра стає на паузу, коли вкладка втрачає фокус.
8. Debug-режим `?debug=1`: лічильник FPS, хітбокси, поточний рівень якості.
9. Продуктивність — 60 FPS і на десктопі, і на сучасному телефоні:
   - пули об'єктів для частинок і жорсткі ліміти частинок у tuning.ts
   - текстури генеруються один раз у BootScene, без перемальовування Graphics щокадру
   - маска обгоряння оновлюється з обмеженою частотою
   - рівні якості high / low: автоматичне зниження (менше частинок, без м'яких тіней),
     якщо середній FPS < 55 протягом 2 с; примусовий вибір через `?quality=low`
   - devicePixelRatio обмежений (наприклад, максимум 2)

Поза обсягом: вода, інші трансформації, згортання аркуша, мета "дістатися центру",
меню, звук, збереження.

## Архітектура гри
- Сцени: BootScene, GameScene, UIScene (HUD: смужка HP).
- Гравець як state machine (Idle, Run, Jump, Fall, Glide, Hurt, Dead), кожен стан в окремому класі.
- Усі параметри (швидкість, гравітація, підйомна сила, шкода, невразливість, ліміти частинок,
  пороги якості) зібрані в одному tuning.ts.
- Рівень описаний TS-об'єктом із типами (не захардкоджений у сцені).
- Кольори гри беруться з дизайн-токенів (див. нижче). Тема (світла/темна) береться
  на момент запуску гри.
- Перед стартом гри шрифти завантажуються через `document.fonts.load`,
  щоб текст у Phaser не мигав запасним шрифтом.

## Візуальний стиль: вибір із варіантів
- Після каркаса підготуй 4 варіанти візуального стилю в паперовій естетиці.
  Варіанти мають відрізнятися між собою помітно, а не лише відтінком кольору.
  Наприклад: теплий васі-папір із чорнилом і червоним акцентом, крафт-папір,
  нічний індиго з вогняними акцентами, газетний папір із півтоновим растром.
  Можеш запропонувати свої.
- Для кожного варіанта на одній сторінці показано, у світлій і темній темі:
  - назву й опис настрою (1–2 речення)
  - палітру (5–7 кольорів із hex) і контраст основних пар тексту (WCAG AA)
  - шрифтову пару з Google Fonts (заголовки + текст, ліцензія OFL; максимум 2 сімейства)
  - текстуру паперу фону
  - ніндзя в станах Idle, Run і Glide
  - фрагмент рівня: платформа, вогняна зона, ворог
  - favicon у розмірах 16, 32 і 180 px
  - OG-картинку 1200×630 у зменшеному вигляді
  - фрагмент сайту: header, h1, абзац, кнопка "Play"
- Усе малюється кодом. Сторінка `/styles/` існує тільки в dev (у build, sitemap і на Pages
  її немає) і відкривається командою `just styles`. Тільки на ній шрифти можна тимчасово
  брати з CDN Google Fonts.
- Після підготовки ЗУПИНИСЬ і дочекайся, поки я оберу варіант (або комбінацію,
  наприклад "палітра B + шрифти A").
- Обраний стиль фіксується як дизайн-токени в `src/theme/tokens.ts` (світла й темна палітра).
  З цього одного джерела беруть стиль гра, CSS сайту (через CSS custom properties)
  і генератор графіки. Інші варіанти й сторінка /styles/ видаляються.

## Шрифти (Google Fonts, self-hosted)
- Обрані шрифти зберігаються в репозиторії (`src/assets/fonts/`): тільки woff2,
  сабсети latin + latin-ext, тільки потрібні накреслення (максимум ~4 файли).
  Поруч лежить файл ліцензії OFL для кожного сімейства.
- Шрифти завантажує один раз скрипт `just fonts` (у Docker, без npm-залежностей).
  Файли комітяться, тож збірка не залежить від мережі. Під час роботи сайт не робить
  жодних запитів до Google Fonts.
- `@font-face` з `font-display: swap`; `<link rel="preload">` для 1–2 ключових файлів;
  метрики запасного шрифту налаштовані (`size-adjust`, `ascent-override`), щоб не було зсуву макета.
- Ці ж шрифти використовуються в згенерованих PNG (OG, іконки з текстом): у контейнері
  збірки шрифти встановлюються для fontconfig або текст перетворюється на контури.
  Перевір, що в PNG не підставляється запасний шрифт.

## Тема сайту
- Світла й темна тема. За замовчуванням береться з `prefers-color-scheme`.
- Перемикач у header з трьома станами: System / Light / Dark. Вибір зберігається
  в localStorage (усі звернення в try/catch).
- Маленький inline-скрипт у `<head>` ставить тему до першого рендеру, щоб не було спалаху
  неправильної теми.
- Без JS сайт працює за системною темою, а перемикач прихований.
- Перемикач доступний: `<button>` з aria-label і aria-pressed або еквівалентом, видимий фокус.
- `<meta name="theme-color">` для обох тем.

## Сторінки
Кожна з окремим URL (усі під BASE_PATH):
- `/` — головна: що це за гра, ідея, згенерована hero-ілюстрація, кнопка "Play"
- `/play/` — гра; `<noscript>` із поясненням і посиланням на /controls/
- `/about/` — сюжет, механіки, технології, плани, розділ "Open source"
- `/controls/` — керування для клавіатури й мобільного
- `/devlog/` — список записів і окремі сторінки записів; перший запис — про прототип
- `/privacy/` — політика конфіденційності: що збирає GA, навіщо, як відкликати згоду
- `/404.html`

Записи devlog описані даними (файли в src/content/devlog/). З них генеруються сторінки
записів, список, sitemap, JSON-LD і OG-картинки записів.
Спільний header/footer вставляється на етапі збірки власним Vite-плагіном
(transformIndexHtml), без додаткових залежностей і без дублювання коду.
Сторінки працюють без JavaScript, адаптивні, анімації поважають `prefers-reduced-motion`.

## Згенерована графіка сайту
Уся графіка сайту генерується скриптом `scripts/generate-assets.ts` під час збірки з
`tokens.ts` і спільних функцій малювання (ті самі форми ніндзя й паперу, що й у грі).
Ручних картинок у репозиторії немає.
- Favicon:
  - `favicon.svg` зі світлим і темним варіантом через `prefers-color-scheme`
  - `favicon-32.png`
  - `apple-touch-icon.png` 180×180 (без прозорості)
  - .ico не потрібен
- Web manifest:
  - іконки 192×192 і 512×512
  - maskable 512×512 із safe zone 80%
  - `theme_color` і `background_color` з токенів
  - `start_url` і `scope` з урахуванням BASE_PATH
- OG / Twitter: `og-image.png` 1200×630, `twitter:card = summary_large_image`.
  Текст на картинці: назва гри + слоган. Шлях стабільний, без хешу, з абсолютним URL.
  Для кожного запису devlog — окрема OG-картинка із заголовком запису.
- Прев'ю на головній: hero-ілюстрація, ніндзя-планер над згорнутим аркушем у горах:
  - inline SVG, що бере кольори з CSS-змінних, тож автоматично підлаштовується під тему
  - явні width/height, не lazy (перший екран)
  - анімація лише CSS, вимикається при `prefers-reduced-motion`

## Google Analytics (GA4) за згодою
- Скрипт gtag.js НЕ завантажується, доки користувач не натисне "Accept". До згоди жодних
  запитів до Google і жодних cookies.
- Consent Mode v2: перед завантаженням gtag.js задається
  `gtag('consent','default',{analytics_storage:'denied', ad_storage:'denied',
  ad_user_data:'denied', ad_personalization:'denied'})`. Після згоди оновлюється тільки
  `analytics_storage: 'granted'`, рекламні параметри завжди лишаються `denied`.
- Банер унизу екрана, `position: fixed`, щоб не було зсуву макета:
  - кнопки "Accept" і "Decline" однакової помітності
  - посилання на /privacy/
  - доступний із клавіатури й для скрінрідерів (role="dialog" або region, aria-label, фокус)
  - підтримує обидві теми
- Вибір зберігається в localStorage (усі звернення в try/catch) разом із версією політики.
  Якщо версія політики змінилась, банер з'являється знову.
- Посилання "Cookie settings" у footer знову відкриває банер. Після відкликання згоди
  gtag вимикається (`window['ga-disable-<ID>'] = true`), а cookies `_ga*` видаляються.
- `GA_MEASUREMENT_ID` — змінна збірки. Якщо вона порожня (dev, локальний Docker),
  банер і GA повністю вимкнені.
- Модуль згоди — маленький окремий скрипт, без Phaser, однаковий для всіх сторінок.
- Ігрові події через обгортку `track()`, яка без згоди нічого не робить:
  `level_start`, `death` (з параметром `cause: fire|fall|enemy`), `checkpoint`,
  `level_complete`, `quality_downgrade`.

## SEO
- Унікальні `<title>` і `<meta name="description">` на кожній сторінці
- Один `<h1>` на сторінку, семантична розмітка (header, main, nav, article, footer)
- `<link rel="canonical">` (абсолютний, із SITE_URL), `lang="en"`, viewport
- Open Graph і Twitter Card (картинки — див. "Згенерована графіка сайту")
- JSON-LD: `VideoGame` на головній (із `sameAs` на репозиторій), `BreadcrumbList` на внутрішніх,
  `Article` для записів devlog
- `sitemap.xml` і `robots.txt` генеруються під час збірки зі списку сторінок, SITE_URL і BASE_PATH.
  robots.txt містить посилання на sitemap.
  (На project site пошуковики ігнорують robots.txt у підпапці, тож sitemap я додам вручну
  через Search Console. Зазнач це в README.)
- 404: `noindex`, без canonical, не потрапляє в sitemap
- `loading="lazy"` для картинок поза першим екраном, явні width/height
- Скрипт `check:seo` перевіряє build:
  - у кожної сторінки є title, description, рівно один h1 і canonical (крім 404)
  - sitemap не містить зайвих сторінок і не пропускає потрібних
  - усі внутрішні посилання й шляхи до ассетів існують у dist/ з урахуванням BASE_PATH
  - на кожній сторінці є посилання на репозиторій і `<link rel="author">`
  - є humans.txt
  - favicon, іконки manifest і OG-картинки існують, мають правильні розміри
    (через sharp metadata) і на них є посилання в head/manifest
  - у dist/ немає посилань на fonts.googleapis.com і fonts.gstatic.com

## Якість коду й тести
- Biome — лінтер і форматер (замість ESLint і Prettier), один конфіг `biome.json`.
- `tsc --noEmit` — частина збірки.
- Vitest — юніт-тести для:
  - переходів state machine гравця
  - валідації даних рівня
  - генерації sitemap і humans.txt
  - логіки згоди: без згоди gtag не завантажується, `track()` нічого не робить;
    відкликання згоди вимикає GA
  - логіки вибору рівня якості
- Playwright smoke e2e на зібраному сайті (desktop Chromium + емуляція телефону), з BASE_PATH для Pages:
  - кожна сторінка відкривається без помилок у консолі
  - неіснуючий URL показує 404
  - /play/ запускає гру: canvas з'являється, BootScene переходить у GameScene
  - на мобільній емуляції видно сенсорні кнопки
  - перемикач теми працює й зберігає вибір
  - з тестовим GA ID: до "Accept" немає жодного запиту до доменів Google;
    після "Accept" є запит на gtag.js (мережа до Google в тестах перехоплюється, а не виконується)
  - на сторінках немає запитів до Google Fonts
- Lighthouse CI на зібраному сайті для всіх сторінок, крім /play/:
  assertions SEO ≥ 0.9, Accessibility ≥ 0.9, Best Practices ≥ 0.9 (desktop і mobile профілі).
  Для /play/ — тільки звіт, без порогів.
- `check:seo` поверх зібраного dist/.

## Docker — єдине середовище
На хості потрібні тільки Docker і just. Node і npm на хості не використовуються:
усі встановлення залежностей, dev-сервер, збірки, лінтинг, тести й перевірки запускаються
в контейнерах. Так само й у CI.
- Multi-stage Dockerfile:
  - `deps` — node:<LTS>-alpine, `npm ci`
  - `dev` — Vite dev-сервер (`--host 0.0.0.0`, HMR, файловий watcher із polling, щоб працював на macOS/Windows)
  - `build` — `npm run build`; build args: `SITE_URL`, `BASE_PATH`, `GA_MEASUREMENT_ID`;
    шрифти проєкту встановлені для fontconfig (для генерації PNG)
  - `test` — lint, typecheck, vitest, check:seo
  - `e2e` — офіційний образ Playwright тієї ж версії, що в package.json; Playwright і Lighthouse CI
    використовують його Chromium
  - `runtime` — caddy:<2.x>-alpine, роздає dist/ під тим самим BASE_PATH, з яким його зібрано
    (щоб локальний запуск у режимі Pages поводився так само, як GitHub Pages)
- docker-compose.yml:
  - `dev` — код змонтований як volume, node_modules в іменованому volume, порт 5173
  - `web` — продакшн-образ на порту 8080
  - файли, створені в контейнері (dist, package-lock.json, звіти), не належать root на хості (UID/GID користувача)
- Caddyfile (тільки для локального запуску; на Pages заголовками керує GitHub):
  - `auto_https off`, слухає :8080
  - gzip (`encode gzip`)
  - `Cache-Control: public, max-age=31536000, immutable` для файлів із хешем і шрифтів;
    `no-cache` для HTML
  - `file_server` під BASE_PATH, `handle_errors` віддає 404.html зі статусом 404
  - `/play` і `/play/` обидва працюють (редирект на слеш — стандартна поведінка file_server)
  - заголовки `X-Content-Type-Options: nosniff` і `Referrer-Policy: strict-origin-when-cross-origin`
- HEALTHCHECK через `wget -q --spider` (curl в alpine немає)
- .dockerignore: node_modules, dist, .git, звіти тестів

## justfile
Усі команди проєкту — тільки через just, кожен рецепт запускає Docker.
`just` без аргументів показує список рецептів. Мінімальний набір:
- `install` — встановити залежності в контейнері (оновлює package-lock.json)
- `dev` — dev-сервер на localhost:5173
- `styles` — сторінка порівняння стилів на localhost:5173/styles/ (тільки до вибору стилю)
- `fonts` — завантажити обрані Google Fonts у репозиторій
- `lint` / `format` — Biome (перевірка / автоформатування)
- `typecheck`, `test`, `check-seo`
- `build` — збірка dist/ (параметри SITE_URL, BASE_PATH, GA_MEASUREMENT_ID зі значеннями за замовчуванням)
- `build-pages` — збірка з налаштуваннями GitHub Pages
- `e2e` — Playwright smoke-тести
- `lighthouse` — Lighthouse CI
- `check` — швидка перевірка: lint + typecheck + test + build + check-seo
- `ci` — повна перевірка: check + e2e + lighthouse (те саме, що в CI)
- `image` — зібрати продакшн-образ
- `up` / `down` / `logs` — продакшн-сайт на localhost:8080 (BASE_PATH=/)
- `preview-pages` — сайт на localhost:8080/origami-ninja/, як на GitHub Pages
- `shell` — shell у dev-контейнері
- `clean` — видалити dist, звіти, volumes і образи проєкту

## CI/CD (GitHub Actions)
- `ci.yml`: на кожен push і pull request запускає `just ci` (усе в Docker, як локально).
  Звіти Playwright і Lighthouse зберігаються як artifacts.
- `deploy.yml`: на push у main і вручну (workflow_dispatch):
  1. `just ci`
  2. `just build-pages`
  3. dist/ витягується з контейнера
  4. `actions/upload-pages-artifact` → `actions/deploy-pages`
  Права: `pages: write`, `id-token: write`. Джерело Pages у налаштуваннях репозиторію — GitHub Actions.
- `GA_MEASUREMENT_ID` береться з repository variable `vars.GA_MEASUREMENT_ID`.
- just встановлюється в CI окремим кроком (наприклад, `extractions/setup-just`).
- Версії actions зафіксовані.

## Готово, коли
- `just dev` запускає гру: можна пробігти рівень, обгоріти у вогні, загинути й відродитися,
  пролетіти прірву планером і дійти до фінішу

- humans.txt відкривається й містить актуальні версії технологій
